# Home 页面重设计：从 Agent Manager 到 AI Companion（事件流版）

---

## 1. 页面名称建议

| 候选 | 含义 | 调性 |
|---|---|---|
| **Pulse** | AI 的生命脉搏，随时感知状态 | 活的、呼吸的、随时在 |
| **Aria** | 独唱/咏叹调，AI 的声音 | 个人化、有温度、有声音感 |
| **Today** | 每日陪伴，时间感知 | 日常的、亲切的、有上下文 |

采用 **Pulse**——它暗示 AI 不是工具列表，而是一个有心跳的存在。用户打开 App 就是感受 AI 的脉搏。

---

## 2. 页面信息架构（事件流版）

> 版本演进：V1（Agent 列表）→ V2（卡片堆叠）→ **V3（事件流 + 全屏 BottomSheet，当前实现）**
> V3 的核心转变：信息单位从「卡片」变为「事件」，操作从「页面上铺开」变为「点击事件 → 弹出框」。

```
┌─────────────────────────────┐
│  ScreenHeader              │
│  "Pulse"        🔔          │  ← 标题 + 通知
├─────────────────────────────┤
│  Good evening.              │  ← 时间感知问候（type-headline）
│  ● I'm here.  Watching...   │  ← Presence 行（呼吸点 + 一句话）
├─────────────────────────────┤
│  NEEDS YOU                  │  ← 事件分区 1（紧急/待办）
│  ┌───────────────────────┐ │
│  │ ACTION                 │ │  ← 类型 = 行首标题
│  │ Review the auth        │ │     事件标题
│  │ migration              │ │
│  │ Session handling is    │ │     摘要
│  │ done — one migration…  │ │
│  │              ⚠ Needs you│ │  ← 状态沉右下角（11px）
│  └───────────────────────┘ │
│                             │
│  TODAY                      │  ← 事件分区 2（今日发生）
│  ┌───────────────────────┐ │
│  │ CALENDAR               │ │
│  │ 3pm with Mei moved to 4│ │
│  │              ✓ Confirmed│ │
│  ├───────────────────────┤ │
│  │ SUBSCRIPTION           │ │
│  │ Coffee subscription…   │ │
│  │              ✓ Let through││
│  ├───────────────────────┤ │
│  │ DRAFT                  │ │
│  │ Reply to the recruiter │ │
│  │              ○ Draft   │ │
│  └───────────────────────┘ │
├─────────────────────────────┤
│  Pulse │ Talk │ Memory │ Me │  ← Bottom Tabs（固定视口底部）
└─────────────────────────────┘
```

### 各区域职责

| 区域 | 职责 | 设计原则 |
|---|---|---|
| 顶部区域 | 问候 + AI 在线指示 | 1 秒内知道 AI 在（呼吸点跳动） |
| 事件分区 | 按紧急度/时间组织事件 | 分区少（≤2），不出现"分类迷宫" |
| 事件单元 | 一个事件 = 一个可点单位 | 类型左上角 → 标题 → 摘要 → 状态右下角 |
| 全屏弹出框 | 事件详情 + 操作 + 指令 | 点击事件后的一切都发生在弹出框内 |

**关键差异（对比 V2 卡片堆叠）：** 首页不再有常驻 Prompt Entry、不再铺行动按钮、不再有 Daily Brief（已迁入 Memory）。首页只有一件事：**事件流**。

## 3. 核心交互设计

### 事件单元（EventItem）

**用户看到的内容：**
- 类型标识（ACTION / CALENDAR / SUBSCRIPTION / DRAFT）作为行首标题
- 事件标题 + 单行摘要
- 状态（Needs you / Confirmed / Draft）沉右下角，缩小一号（11px）

**设计规则：**
- 行内字体统一（13px / 500，同 "I'm here"），仅用颜色分层：类型/摘要 muted、标题 ink
- 无 chevron（">"）——可点性由整行按压反馈表达（`:active` 变 surface-2）
- 事件行可点 → 打开全屏 BottomSheet

### 全屏 BottomSheet（事件详情）

**用户看到的内容：**
- 类型 + 状态 + 关闭（X）
- 事件标题（headline）
- 事件完整上下文（body）
- 行动按钮（该事件的 Review / Pause / Send 等）
- 底部 Prompt Entry：输入框 + 语音输入 + 发送

**AI 视角表达：**
> 点击 "Review the auth migration" → "这是迁移的完整上下文。你可以在这里直接回复我，也可以说 '继续做'。"

**设计规则：**
- 撑满整个屏幕：详情、操作、对话在同一场景，不打断上下文
- Prompt Entry 只存在于事件场景内（"Ask about this…"），首页不留常驻输入
- 语音输入按钮预留（Voice / mic icon）

## 4. 用户进入 App 后 10 秒体验流程

```
时间    用户看到                      用户感受
─────────────────────────────────────────────────────
0s     页面加载                       "打开了"
       顶部："Good evening"
       ● 呼吸点在跳动

1s     "I'm here. Watching 3        "AI 在"
       projects and your day."

2s     事件流出现                     "有什么新鲜事"
       NEEDS YOU: "Review the
       auth migration"

4s     读到事件摘要                   "需要我审核"
       "Session handling is done
       — blocking tomorrow's deploy"

6s     点击事件 → 全屏弹出框          "详情在这"
       完整上下文 + Review/Pause

8s     目光到达底部输入框             "可以直接在这说"
       "Ask about this…" + 🎤 + ▶

10s    用户决定：                     开始交互
       - 点 "Review" 进 Talk        或
       - 输入/语音指令               或
       - 关闭，继续扫事件流
```

**体验设计意图：**

| 秒数 | 意图 |
|---|---|
| 0-2s | **感知 AI 存在** - 呼吸点 + 第一人称 |
| 2-4s | **扫到事件** - 事件流取代卡片堆叠 |
| 4-6s | **判断是否需要我** - 状态右下角一瞥可辨 |
| 6-8s | **进入事件上下文** - 全屏弹出框不打断思考 |
| 8-10s | **就地行动** - 操作按钮 + 指令输入都在弹出框 |

核心节奏：**感知 -> 扫描 -> 判断 -> 深入 -> 行动**

## 5. 传统 Agent App vs JARVIS 风格 App UI 差异

| 维度 | 传统 Agent App | JARVIS 风格 App |
|---|---|---|
| **首页主内容** | Agent 列表（5 张卡片） | AI 事件流（一个单位 = 一个事件） |
| **信息组织** | 所有 Agent 平铺 | 按"需要你/今日"分区 |
| **状态表达** | "OpenCode: Running" | "I'm here." + 事件状态沉右下角 |
| **人称** | 第三人称（它/系统） | 第一人称（I）+ 对用户（you） |
| **活动展示** | 实时 log feed | 事件流（今日总结在 Memory） |
| **主动性** | 等用户操作 | AI 主动汇报 + 标记"需要你" |
| **用户角色** | 管理者，监督多个 worker | 伙伴，与 AI 对话 |
| **视觉重心** | 数据密集，卡片网格 | 事件流 + 留白 |
| **操作入口** | 点击卡片 -> 详情页 | 点击事件 -> 全屏弹出框（就地操作） |
| **情感调性** | 机械、监控、管理 | 个人、陪伴、对话 |
| **时间感知** | 无（静态列表） | 有（Good evening / Today） |

### 核心转变

```
传统:  用户 -> 查看 Agent 列表 -> 选择一个 -> 查看详情 -> 操作

JARVIS: 用户 -> 感知 AI 存在 -> 扫描事件流 -> 点击事件 ->
        弹出框内直接操作/对话
```

**本质区别：** 传统 App 把 AI 当进程管理；JARVIS App 把 AI 当伙伴对话。前者是工具，后者是关系。

## 6. 与 V2 信息架构的衔接

| 模块 | V2 决定 | V3（事件流版）演进 |
|---|---|---|
| Daily Brief | 首页的一段总结 | 迁入 Memory 页，作为 "Today" 今日总结模块 |
| Prompt Entry | 首页底部常驻 | 移入事件全屏弹出框，按事件上下文提问 |
| 行动按钮 | 首页卡片上铺开 | 移入对应事件的弹出框 |
| Presence | 卡片式 "I'm here" | 精简为一行（呼吸点 + 一句话） |
| Insights | 融入 Daily Brief | 以事件形式出现在事件流（如 DRAFT 事件） |

**一句话：V2 把骨架从「Dashboard」变成「AI 说话」，V3 把「说话」变成「可点击的事件」。**
